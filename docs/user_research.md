# 用户研究

## 1. 目标用户画像

### 画像 A：AI 产品经理（小林，26 岁）

- **背景**：负责公司客服大模型产品，需推动从 POC 到上线
- **目标**：建立评测标准、选型最优模型、输出迭代方案给研发
- **技术能力**：了解 Prompt 与 RAG 概念，会基础 Python
- **使用频率**：每周 3-5 次评测会话

### 画像 B：AI 应用开发者（阿杰，28 岁）

- **背景**：全栈开发，负责 RAG 知识库问答系统
- **目标**：快速验证 Prompt 与检索策略，减少返工
- **技术能力**：熟练 Python，熟悉 OpenAI API
- **使用频率**：日常开发调试

### 画像 C：企业 AI 团队负责人（王总，35 岁）

- **背景**：评估是否采购/自研大模型应用
- **目标**：看到可量化的评测数据与 Demo
- **技术能力**：产品视角，关注 ROI 与风险
- **使用频率**：阶段性评审

## 2. 典型使用场景

### 场景 1：新 Prompt 上线前验证
> 产品经理在「Prompt 实验台」选择「客服问答」场景，输入新版 System Prompt，运行 5 组测试问题，保存实验并对比旧版响应质量。

### 场景 2：模型选型决策
> 开发者在「多模型对比」输入同一复杂问题，对比 GPT-4o-mini、DeepSeek、方舟模型，根据评分与成本选择生产模型。

### 场景 3：RAG 知识库质量排查
> 上传产品手册 PDF，针对易错问题提问，标注「幻觉」「引用错误」标签，在看板查看高频问题类型。

### 场景 4：迭代复盘
> 每周打开「评测看板」查看平均评分与标签分布，使用「AI 优化建议」生成下周 Prompt 与检索策略改进清单。

## 3. 用户痛点（调研摘要）

| 痛点 | 用户原话（模拟） | 优先级 |
|------|------------------|--------|
| 实验难沉淀 | 「每次测试都在 ChatGPT 里，找不到历史记录」 | P0 |
| 对比不系统 | 「不知道哪个模型性价比最高」 | P0 |
| RAG 问题难归类 | 「用户说回答不对，但说不清是检索还是生成的问题」 | P1 |
| 缺少数据支撑 | 「老板问优化效果，我只能凭感觉说」 | P1 |
| 优化无方向 | 「知道有问题，但不知道 Prompt 该怎么改」 | P2 |

## 4. 竞品分析（简版）

| 产品 | 优势 | 劣势 | 与本项目差异 |
|------|------|------|--------------|
| **LangSmith** | 链路追踪、评测集、生态完善 | 偏开发者、需 LangChain 集成、付费 | 本项目更轻量、面向产品经理、独立 Streamlit |
| **PromptLayer** | Prompt 版本管理、日志 | 偏工程、RAG 评测弱 | 本项目覆盖 RAG + 看板 + AI 建议 |
| **Coze / 扣子** | 低代码 Agent、易上手 | 评测与数据导出有限 | 本项目专注评测闭环，非 Agent 搭建 |
| **人工 Excel** | 零成本 | 不可扩展、无 API 调用 | 本项目自动化调用与可视化 |

### 差异化定位

**AI Product Evaluation Workbench** = 轻量 + 全流程 + 产品视角 + 可部署 Demo

- 不绑定特定框架（OpenAI-compatible 通用）
- 覆盖 Prompt → 模型 → RAG → 反馈 → 建议 完整链路
- 适合实习/portfolio 展示产品思维与工程能力
