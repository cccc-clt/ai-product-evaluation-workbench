# 产品需求文档 (PRD)

## 1. 项目背景

大模型应用快速普及，但多数团队在大模型应用上线前缺乏系统化的评测与迭代工具。产品经理和开发者往往使用零散脚本或手动对话测试 Prompt，难以沉淀实验数据、对比模型效果、追踪 RAG 质量，也无法形成「测试 → 反馈 → 优化」的产品闭环。

**AI Product Evaluation Workbench** 旨在提供一个轻量、可部署的 Web 平台，模拟大模型应用上线前的完整评测流程。

## 2. 用户痛点

| 痛点 | 描述 |
|------|------|
| Prompt 调试分散 | 不同场景 Prompt 保存在本地文件或聊天记录，难以版本管理 |
| 模型选型困难 | 缺少同一问题下多模型的结构化对比与评分记录 |
| RAG 质量难量化 | 文档问答幻觉、引用错误等问题缺乏标签化反馈机制 |
| 数据不可见 | 实验结果无法聚合分析，优化决策依赖主观感受 |
| 优化建议靠经验 | 缺少基于数据的 AI 辅助优化建议 |

## 3. 目标用户

- **AI 产品经理**：设计评测流程、定义指标、输出优化方案
- **AI 应用开发者**：调试 Prompt、验证 RAG、对比模型
- **企业 AI 团队**：建立内部评测规范

## 4. 核心功能

### 4.1 Prompt 实验台
- 6 种业务场景（客服、总结、润色、分析、代码、自定义）
- System/User Prompt 编辑、模型参数调节
- 响应时间、Token、成本估算
- 实验记录保存与版本追踪

### 4.2 多模型效果对比
- 同一问题调用多个模型
- 回答、延迟、成本对比
- 人工评分（1-5）与备注
- 对比记录持久化

### 4.3 RAG 文档问答评测
- PDF/TXT 上传与解析
- 文档分块与向量索引
- 检索增强问答 + 引用溯源
- 8 类问题标签 + 用户评分

### 4.4 用户反馈与评测看板
- 历史实验聚合
- 模型得分、场景分布、标签分布图表
- 最近实验记录表

### 4.5 AI 自动优化建议
- 读取低分样本与反馈标签
- 生成 Prompt/模型/参数/RAG/体验五类建议
- 结构化展示与报告保存

## 5. 用户流程

```
配置 API → Prompt 实验 → 多模型对比 → RAG 评测 → 保存反馈
                                              ↓
                                    评测看板分析 ← AI 优化建议
```

**典型路径：**
1. 用户在侧边栏配置 API Key 与 Base URL
2. 在 Prompt 实验台选择「客服问答」场景，调试 Prompt 并保存
3. 在多模型对比中输入同一问题，对比 2-3 个模型并打分
4. 上传产品文档 PDF，在 RAG 模块提问并标注「幻觉」等标签
5. 在评测看板查看模型得分与标签分布
6. 在 AI 优化建议页生成结构化改进方案

## 6. MVP 范围

**包含：**
- 5 个功能页面（Prompt / 对比 / RAG / 看板 / 建议）
- SQLite 本地存储
- ChromaDB 向量检索
- OpenAI-compatible API 调用
- 双 Embedding 模式（API / 本地）
- 基础成本估算与 Token 统计

**不包含（后续迭代）：**
- 用户登录与权限
- 批量测试集自动化
- LLM-as-Judge 自动评分
- 团队协作与分享

## 7. 评测指标

| 维度 | 指标 |
|------|------|
| 模型 | 响应时间、Token 消耗、估算成本、人工评分 |
| Prompt | 场景覆盖、版本数、实验次数 |
| RAG | 引用准确率（人工）、问题标签分布、用户评分 |
| 整体 | 平均评分、低分样本数、高频失败原因 |

## 8. 迭代计划

| 阶段 | 内容 |
|------|------|
| V1.0 (MVP) | 5 模块 + SQLite + 基础看板 |
| V1.1 | 批量测试集、导出报告 |
| V1.2 | LLM-as-Judge、A/B 测试 |
| V2.0 | 团队协作、火山方舟深度集成 |
